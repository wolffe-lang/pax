pxg image integration
2026-11-13T06:32:42Z

Scope
Build the production pxg executable from a full public source commit using
that source tree's own Wolf, Lupin and std pins. Build in two independent
checkouts, require equal bytes, and reject a dynamic executable. Install
only /bin/pxg in both distribution variants; do not ship the failpoint or
qualification probes. Record the source pin in /etc/pax-release and the
binary in the ordinary image file inventory.

Prediction
The existing release identity test will first fail image-pxg-pin-missing.
After integration, the archive and release tests will verify the source
pin, production bytes, mode, owner and checksum refusals. The latest-image
resolver will resolve pxg just like the other source-built programs.
The installer suite will carry the same production bytes onto plain ext2.
An installed-disk session will run version and version comparison, refuse
live install/remove/upgrade by name, and refuse init on an existing ext2
subdirectory before reading a deliberately missing trust root. It will
leave no package-manager state behind. These are reader/refusal rows, not
transaction, journal-durability or package-adoption qualification.

Implementation order
1. Commit the failing release/archive checks.
2. Add the source pin, static builder and production-only image input.
3. Add installed-ext2 reader/refusal rows to the existing installer suite.
4. Run standalone preflight, then one committed-head checkpoint.
5. Plant a production image omission and retain its named failing row.

Out of scope
No filesystem conversion, new journal qualification, adoption, real
packages, networking, signing keys, publishing or real hardware changes.
