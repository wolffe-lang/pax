# The rows where PAX's sudo differs from Ubuntu's sudo 1.9.15p5 on purpose, each with its reason.
# A line is  REGEX <TAB> REASON ; REGEX is searched in "CONFIGURATION: ROW". A row named here must
# differ (a stale name is a failure) and every other row must be the same. Content rules start
# with `text:` and are searched in Ubuntu's text of the row instead.
# px106 took away the three names for "Linux asks for a password before it says no": PAX's sudo
# asks too, so those rows are the same now (a stale name is a failure).
text:Sudo version	-V prints Ubuntu's version and plugin lines; PAX's own version and the R6 claim
details: pax-h-cmd$	-h HOST (run on a host) is not built; PAX prints the help
hostile .*: (syntax-error|syntax-error-main)-	Linux reports a syntax error with file:line:column and a caret and carries on with the rest of the policy; PAX's contract denies everything on a parse error, naming the file and line
hostile .*: relative-cmd-	the same: a relative command path is a parse error that denies everything
hostile .*: cmnd-alias-	Cmnd_Alias is not in the subset: a parse error that denies everything
hostile .*: cmd-args-	a command with arguments is not in the subset: a parse error that denies everything
hostile .*: host-name-	a host other than ALL is not in the subset: a parse error that denies everything
hostile .*: long-line-	a line over 1024 bytes is refused by name
hostile .*: long-arg(v)?$	Ubuntu's sudo bounds the arguments it passes; PAX's passes what execve takes
