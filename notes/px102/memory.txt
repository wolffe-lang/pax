px102 — memory rows beyond ELF text/data: the prediction, written
2026-11-06 at 9a2109a4, before the witness has run anywhere. Sources:
ptrace(2) (PEEKTEXT/PEEKDATA/POKETEXT/POKEDATA), proc_pid_mem(5),
pread(2), lseek(2), mmap(2), mprotect(2). No kernel source.

One witness, mode `memory`: the TRACEME child re-execs trace as role-mem,
which maps fixed regions and stops at int3:
  MA  0x500000, two private anonymous pages, bytes i*7+1
  MB  0x502000, one page of 0x5a, then mprotect PROT_NONE
  MC  0x503000, a read-only private file page (the trace binary, offset 0)
  MC2 0x504000, a second private mapping of the same file page
  MD  0x505000, one shared anonymous page of 0x3c; 0x506000 unmapped
Rows, each judged by check.py's named span plus the whole transcript:
  mem-cross-page   PEEK/POKE of a word straddling MA's page boundary.
  mem-prot-none    PEEK and POKE on PROT_NONE.
  mem-private-file POKE into a read-only private file page: it must take
                   (a breakpoint into text), and the other private mapping
                   of the same file page must keep the original byte.
  mem-shared       POKE into a shared page; the edge row reads/writes a
                   word that runs off the end of the mapping; kernel and
                   non-canonical addresses.
  mem-proc-mem     /proc/<pid>/mem pread/pwrite across a page boundary,
                   a short count at the end of a mapping, zero length,
                   a kernel address, a negative offset, PROT_NONE and a
                   read-only page, lseek+read.
  mem-proc-self    /proc/self/mem read and write of the tracer's own data.
  mem-held-exec    a descriptor opened before the target's exec reads
                   EOF (0) and writes 0 after it; a fresh open sees the
                   new image.
The target also reports, in r15 at a second stop, whether it saw the
pokes (shared byte, private file byte, the other mapping unchanged, the
cross-page word).
Prediction: Linux forces PEEK/POKE through read-only and PROT_NONE
private mappings (copy on write) but not through a shared one's file;
a short pread/pwrite at a mapping end returns the bytes reached and a
hole at the start gives -EIO (5). PAX's position is unknown; the
transcript is the reference wherever the two disagree.

Measured on Linux (78369437's binaries; a fresh container per take; 3
takes as uid 0 and 3 as uid 1000, all byte-identical, uid 0 equal to
uid 1000): END linux-memory-0 exit=0 takes=3, END linux-memory-1000
exit=0 takes=3. Reference: tests/mpx5-trace.d/memory.linux.
Disagreements with the prediction, recorded not hidden:
  - PEEK and POKE reach a PROT_NONE page (the poke took, mem.none.after
    0x77), and so does /proc/<pid>/mem, which also pwrites it.
  - A word straddling the end of a mapping fails -EIO (-5) for PEEK, and
    for POKE the bytes below the mapping's end are still written before
    the failure (mem.edge.pread shows 3c then seven zero bytes).
  - A kernel address and a negative offset through /proc/<pid>/mem are
    -EINVAL (-22), and PEEK of a kernel or non-canonical address -EIO.
  - After the target's exec, a descriptor opened before it reads 0 and
    writes 0; a fresh open reads -EIO at the old address.
