P1. The loader does NOT take merged rows without a format change:
    tools/mkfont emits a 256-entry table indexed by code point and
    kernel/screen keeps 8 glyph bits a cell (bits 0-7), so a glyph above
    U+00FF needs a code-point map in boot/font.S and a wider glyph field
    in the cell (bits 17-31 are free). The BDF format itself needs
    nothing: pax-extra.bdf rows are the same BBX 8 16 0 -4 shape.
P2. A braille generator with 2x2-pixel dots in columns 1-2 and 5-6 and
    rows 4k+1..4k+2 reproduces Spleen's 256 braille glyphs bit for bit,
    and plain rectangles reproduce Spleen's 29 non-shade block elements;
    Spleen's three shades are 25/50/75 % dithers but not one nested
    ordered-dither matrix.
P3. Keys through PAX's PS/2 driver: every one the games bind arrives as
    the games' decoders expect -- arrows ESC [ A-D, Shift+arrows
    ESC [ 1 ; 2 A-D (pack's parry on Shift+Down), Space 20, Enter 0D, q
    71, Esc 1B alone -- because kernel/console's header already serves
    the measured VT's modified arrows (px59, vt2.rows). Falsified by any
    key the games' --record files do not name as typed.
