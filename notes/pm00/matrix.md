# pm00 comparison matrix

Read on 2026-11-02. [SOURCES.md](SOURCES.md) resolves each bracketed ID to a URL, date and use. **Documented** means the cited public documentation says it; **unknown** means this study did not establish it, not that an implementation lacks it. No implementation source was used as evidence and no package-manager binary was run; the main note and SOURCES record one excluded incidental search snippet. TUF is an update-security framework, Go/Cargo/wolf pkg are source-distribution systems, and OSTree is a tree-distribution substrate: marking OS installation facets inapplicable is more accurate than forcing them into a distro model.

## Why these systems matter, and what failed publicly

| System | What it optimizes / why keep the distinction | Public failure or evidence boundary |
|---|---|---|
| pacman, makepkg, libalpm | Simple binary distro workflow, separate build recipe and transaction library; inspectable package/DB artifacts and powerful user control [A01–02]. | CVE-2019-9686 URL traversal; 2019 script/injection tracker entries [A14]: verification must not bypass safe path/command handling. Current vulnerability is not alleged. |
| apk-tools v2 and v3 | Small distro state/world model; v3 replaces tar-centric metadata with ADB/data separation rather than being a cosmetic codec change [A03–05]. | CVE-2021-30139 affected older tar parsing [A15], not evidence of an ADB/v3 flaw; authenticated data still needs a bounded parser. |
| XBPS | Binary package tool with explicit configs/holds/alternatives, independent package creation and service lifecycle [A06–08]. | 2021 repository-signing disruption [A16]: signing availability and recovery belong in the design, not only in release automation. |
| dpkg and APT | Split low-level installed-state machinery from candidate/dependency/repository policy [A09–10]. | DSA-4371 HTTP redirect injection [A17]: transport parsing can defeat a trust design if untrusted headers cross protocol boundaries. |
| RPM, DNF, libsolv | Metadata/script-bearing package format, explicit candidate/history policy and satisfiability engine are different layers [A11–13]. | CVE-2021-3421 crafted-package DB corruption [A18]: a signature or SAT result does not prove robust installation state. |
| Nix and Guix | Dependency-specific immutable storage and separate activation/GC avoid overwriting the only previous payload [I01]; Guix uses profile generations and reachability with explicit collision policy [I09–12]. | Coordinated 2025 privilege-escalation advisory [I08], with Guix CVEs separately attributed: build users/daemons are a trust boundary. |
| Homebrew bottles | Prebuilt artifacts tagged for platform/Cellar/relocation, with source build as a separate route [I02]. | 2021-04-21 Cask review/automerge diff-classification incident [I13]: authorization of publication cannot rest only on a diff classifier. This was cask automation, not evidence of formula-bottle compromise. |
| OSTree and Flatpak | Tree/deployment identity versus app/runtime identity; binary rollback does not roll shared /var backwards [I03–05]. | OSTree GHSA-7cgc-gp99-6jmm (2026), static-delta memory/storage exhaustion, fixed 2026.3 [I14]; Flatpak CVE-2024-32462 (2024), portal-command option interpretation sandbox escape [I15]. Different boundaries: bounded download is not bounded expansion, and signed app metadata is not safe command-line input. |
| TUF and Cappos | Analyze mirror/network compromise, stale signed material, mixed metadata and delegated/key-compromise recovery separately [T01–02]. | Cappos' 2008 attack study is historical empirical evidence, not an allegation against current versions; TUF documents residual clock/availability limits. |
| Go proxy and checksum DB | Static cacheable distribution plus independently checked append-only version-content identity, MVS for compatible module graphs [I06]. | GO-2023-2042 / CVE-2023-39320, crafted go.mod toolchain directive could execute relative binaries/scripts, fixed go1.21.1 [I16]. Proxy-delivered modules included; this is metadata execution, **not sumdb forgery**. |
| Cargo sparse index | Fetch just needed per-package metadata via ordinary HTTP validators instead of a whole Git index [I07]. | CVE-2026-33056: archive extraction could change permissions outside the package [I17]; crates.io filtered uploads, advisory announced a forthcoming Rust 1.94.1 fix. This source alone does not prove shipment; this is extraction, not sparse-index transport. Stale CDN metadata is a separate documented operational hazard [I07]. |
| wolf pkg / s51 | Data-only manifests, source-tree MVS/ledger/capabilities; a system installer must not quietly weaken those contracts [P03,P15]. | Specification limits are not a public incident: registry-shaped entries/MVS transport integration and keyed-b3 log tag have narrower scope than a publicly verifiable distro root. No verified public wolf-pkg incident was found in the consulted sources; this is not an assurance that none exists. |

## Compression evidence, not a PAX benchmark

All codecs need authenticated compressed length, aggregate uncompressed length, file count and work/window caps; a codec checksum is not a signature [F02–05]. None has one universal ratio or speed.

| Choice | Evidence and tradeoff | Wolf/PAX consequence |
|---|---|---|
| None | Encoded tar bytes/input tar bytes = 1; archive headers and padding remain overhead versus original file contents. Avoids decode CPU but costs transfer/storage; no speed number measured. | First path avoids new decoder and keeps memory dominated by bounded I/O buffers, not package-sized output. |
| gzip/deflate | RFC1951 gives 32 KiB history, not an output cap; gzip ISIZE is modulo 2^32 [F03–04]. Den's historical **whole-file-driver** 100 MB measurements: encode 29.25 MB/s random / 157.47 zero, decode 67.04 / 77.57; peak decoder RSS 426,292 / 328,852 KiB [P13]. These do not predict a streaming package decoder. | Existing raw/zlib codec is leverage, but gzip framing/CRC/member policy and streaming remain work. Do not allocate from ISIZE or use embedded filenames as paths. |
| zstd | RFC8878 permits very large windows/content sizes and optional size; cap before allocation [F02]. Vendor 2016 Silesia/in-memory report (zstd1.0, E5-2678 v3, CentOS7, GCC6) says 3–5x faster compression at similar ratio and ~550 versus ~270 MB/s decode versus zlib [F07]. Different tar/RAM-disk experiment: level3 zstd 67,432,740 bytes versus level6 gzip 68,235,522 bytes. | Promising later default, **not a wolf benchmark**; implement/qualify bounded decode first and measure on PAX package corpus. Exclude external dictionaries/skippable frames initially. |
| xz | Rich filter/index/check format, LZMA2 dictionaries up to 2^32−1 bytes; format doc alone is not the full LZMA2 algorithm spec [F05]. Historical vendor comparison qualitatively favors density but slower compression; numeric xz chart not read [F07]. | More research/decoder surface; no measured PAX gain to justify first-path dependency. |

## Supplemental specification readings

The following evidence completes the cited cells without adding a second facet matrix. Limits still marked unknown above remain unknown.

- **Arch format/build:** `.PKGINFO` is root-level key=value data including relations and backup paths; `.BUILDINFO` records PKGBUILD hash, complete build-environment packages, tool/options/environment and timestamp; gzip `.MTREE` records paths/types/modes/owners/times, file sizes/SHA-256 and symlink targets [A20–22]. These are strong inputs to reproducibility and installed-file verification, not a reproducibility proof. **libalpm hooks:** package/path triggers and install/upgrade/remove operations, alphabetical hook order, pre-transaction AbortOnFail, post hooks only for successful transactions, higher-priority name override/disable [A19]. Those are action ordering rules, not filesystem rollback. ArchWiki's explicit unsupported-partial-upgrade page was not successfully read; the PAX no-partial-upgrade policy is our recommendation, not a misattributed fetched quote.
- **Alpine building:** abuild phases include validation, dependency setup, fetch/extract/prepare, users, build/check/package; rootbld uses a clean chroot, rootpkg uses fakeroot, SOURCE_DATE_EPOCH is the reference timestamp [A30]. Executable build phases remain trusted build inputs. **XBPS layout/building:** `/var/db/xbps/pkgdb-0.38.plist`, per-package `.<pkgname>-files.plist`, `<arch>-repodata`, `/var/cache/xbps`; paths alone establish no crash protocol [A28]. xbps-src documentation describes non-root masterdir/chroot/user-namespace isolation, clean-root recreation and explicit non-reproducibility of host-influenced source bootstrap [A29].
- **Debian format/order/relations:** ar container with `debian-binary`, `control.tar`, `data.tar`; control supports none/gzip/xz/zstd, data also historical bzip2/lzma [A23]. Epoch/upstream/revision order alternates nondigit/digit runs, with special tilde and numeric comparison [A24]. `Pre-Depends` constrains unpacking, `Depends` configuration; `Breaks` and `Conflicts` differ; versioned Provides permits `=` only; Replaces authorizes specific file takeover and is not an unconstrained overwrite switch [A25]. PAX can choose a smaller schema without claiming Debian parity.
- **RPM:** signature/header/cpio payload and spec/source/patch source RPMs [A26]; compression flags allow none/gzip/bzip2/xz/lzma/zstd, subject to build support, with a threading/reproducibility warning [A27]. `%config(noreplace)` preserves modified config and places differing incoming defaults in `.rpmnew` [A26]. These pages do not establish the full binary layout or local DB recovery algorithm.
- **Guix (third-party manual mirror, version unestablished):** input-derived `/gnu/store` variants, isolated-build intent and substitutes [I09]; Scheme package definitions/manifests and explicit name/version/output selection, profile transactions/generations/rollback, conflicting variants in one profile rejected by default even though their store paths coexist [I10]. Substitute ACL authorizes public keys and trusts the server's outputs [I11], not automatic TUF freshness. Profiles/old generations/running processes retain store objects; GC follows reachability and live-item deletion fails. Repair is explicitly not atomic [I12]. Archive codec, installed DB schema, crash durability, delta transport and precise activation-hook policy were not established by these mirror pages.

The study deliberately stops short of inventing undocumented durability claims or exact implementation layouts. These remaining gaps do not authorize a build lane to read forbidden source; future qualification uses specifications and black-box fixtures under that lane's contract.
