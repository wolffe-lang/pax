Prediction before the census and plan

Documentation inspection should distinguish the host builder's ext3 default
from the on-machine installer's plain ext2 output. The seven reported journal
failure paths in pax#411 should prevent a durability recommendation until their
failure-injection rows pass. A filesystem menu alone should not remove either
the formatter's file-size bound or the backend's volume/file bounds.

The smallest useful next format choice should be an explicitly qualified ext3
profile, not a general ext4 or btrfs writer. A shared tree abstraction is likely
to exist without a documented format-independent backend contract. Restore
should remain blocked on metadata/extent capability qualification even when
the root's format can represent those features.

Validation: inventory only public documentation and recorded test output; read
no kernel, formatter or installer implementation. Count inspected evidence and
label documentation, historical observations, new measurements and estimates
separately. Check links, exact scripted tokens and five-section note structure;
plant a wrong installer format in an off-line note copy so the consistency row
must fail before accepting the corrected note. No new filesystem or disk probe
is promised. No physical disk is used.
