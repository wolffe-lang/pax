What was done
Three Wolf formatters under user/disktools, a shared bounded byte layer and
static builders. GPT seeds match mkgpt; FAT has mirrored tables, FSInfo,
VFAT/CP850 aliases and streamed copies; ext2 has bitmaps, groups, backup
superblocks, sparse file maps, metadata manifests and links. No kernel edit.
The pinned Limine source is not opened or modified; a cc wrapper adds only
-static -no-pie and the resulting Linux binary runs unchanged on PAX.
The explicit alternate-writer ext2 root leg leaves ext3's default untouched.
A portable CI suite includes independent Linux oracles, raw Limine equality,
a disk built on the second PAX disk and the persistent playground session.

Oracle findings
- sgdisk -v can exit 0 and say 'No problems found' AFTER warning that the
  backup CRC is bad and regenerating a backup in memory. Reject Warning! too.
- fsck.fat -n can exit 0 after wrong LFN checksums and 'Not auto-correcting
  this'. The gate accepts only its two clean output lines.
- mtools 4.0.49 truncates a supplementary character to its low 16 bits. Keep
  correct UTF-16 surrogate pairs, name the oracle's defect independently.
- The oracle container needs its own binary gconv modules; setting their
  path globally broke Ubuntu xorriso. Only oracle wrappers set that path.
