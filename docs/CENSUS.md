# CENSUS — the Linux system calls a reference userspace makes

px04, 2026-10-04. The measured list that sets P3's lane order and turns
"ABI parity" (`sprints/pax/index.md`) into a number: **ABI parity is the
fraction of the union below that PAX implements with Linux's observable
behaviour.** No kernel code; every table here is generated by
`tools/census/report.py` from the committed tallies in `tools/census/out/`,
and `tests/census` (CI job `census`) fails if any of them is stale.

## How it was measured

Every workload ran in a throwaway rootless podman container on kasumi
(host kernel 7.2.3-1-cachyos), from `archlinux:base-devel` pinned by
digest (`sha256:8185e444…`) and brought to Arch of 2026-10-04 by
`pacman -Syu` (image `out/image-id.txt`; every package version in
`out/image-pacman-Q.txt`: glibc 2.44, bash 5.3.20, dash 0.5.13.4,
pacman 7.1.0, gcc 16.2.1, make 4.4.1, OpenSSH 10.5p1, curl 8.22.0,
strace 7.2, gdb 18.1). The traced programs not from Arch were fetched by
digest (`tools/census/inside/pins.sh`): wolf 0.2.22's release archive
built boreutils at `010f3144a9ba…` twice — **dynamic**, exactly as
`tools/build` links it (PIE, `ld.so`, libc, libm, libgcc_s), and
**static**, the same link with `-static`, which is M-PX3's binary — and
lobo is its 0.1.1 release archive.

Each workload ran twice, each time in a fresh container: once under
`strace -ff -q -y -s 128 -o` (one raw file per process: the census's
input) and once under `strace -f -c` (strace's own whole-tree summary,
kept as a cross-check: every call the census counts also appears there,
except `exit`/`exit_group`, which `-c` never lists, and one rare call
named under "Run-to-run noise" below). Containers ran with
`--security-opt seccomp=unconfined` (podman's default filter answers
calls a real system makes) and `--cap-add SYS_PTRACE` inside the user
namespace (without it strace cannot read the arguments of sshd's
unprivileged session child).

**What is counted.** `tools/census/tally.py` attributes every call to the
*process image* that made it: a process starts with the image of whoever
cloned it, a successful `execve` switches it (and itself belongs to the
new image), and a thread inherits its creator's. Each workload names the
images it counts (its `SCOPE`): boreutils' suite is driven by a python
harness that also runs GNU's side, so only the boreutils binaries are
counted; the shells count only themselves; pacman and cc count their
whole tree (gpg, hooks, `cc1`, `as`, `ld` are what building and
installing need); sshd counts sshd, `sshd-session`, `sshd-auth` and
`sftp-server`, not the user's shell.

**The workloads** (`tools/census/workloads/`), in milestone order:

- `boreutils-static`, `boreutils-dynamic`: boreutils' own differential
  suite (`tools/difftest`, every case file; 2,642 runs of 27 utilities).
  The image's coreutils is 9.12, not the 9.11 oracle of record, so the
  suite runs with `BORE_ORACLE_ANY=1`, and five `head`/`tail` banner
  cases differ from 9.12 (workload rc 1; the same five in every run,
  traced, untraced and wrapped); the calls are the subject, not the
  verdicts.
- `lobo`: lobo 0.1.1 serving the reel's site as the reel drives it:
  `lobo -t`, `serve`, pages, the 1.3 MB file, a range, a 404,
  `/metrics`, keep-alive, the control socket, then scene 4's reload with
  a slow download held across it, the old generation retired, and
  `lobo -s stop`.
- `dash`, `bash`: `tools/census/shell/census.sh` (the POSIX shapes real
  scripts use), `bashisms.sh` (bash only), a login shell's startup, and
  a piped `-i` shell.
- `pacman`: `-Syy`, `-Syu` (a no-op: the image had just been upgraded),
  `-S jq tree nginx` (download, signature check, extraction, hooks),
  `-Qi`, `-Qkk`, `-Rns`.
- `cc`: `make` building `tools/census/cc/` (two translation units, a
  header, an archive, a link), running it, `make clean`.
- `sshd`: one key-authenticated user: a command, a pty session
  (`ssh -tt`), and `scp` both ways.
- `curl`: https, an http-to-https redirect, a 71 MB release download.

What the predictions missed, measured: the static build is nearly as
wide as the dynamic one: they share 24 calls, the dynamic build adds
only `ld.so`'s `access`, `newfstatat` and `rt_sigprocmask`, and the
static one adds `readlinkat` (of `/proc/self/exe`, on every start) and
the rare `clock_gettime`. pacman's breadth is pacman's own (74 of its
88; gpg, gpgsm, gpgconf, ldconfig and the hooks add 14), and sshd's is
privilege separation's: `sshd-session` alone makes 82 of sshd's 89.

### M-PX3, measured smaller: the calls a kernel may answer ENOSYS

A call a program makes is not necessarily a call it needs. For every
call the static build made, `tools/census/inside/inject.sh` reran the
whole suite with that one call answered `-ENOSYS` in every boreutils

## The proposed P3 lane order

Five lanes, in this order, each with its calls by the milestone that
first needs them. The first three together are M-PX3; none of them needs
a signal or a socket.

<!-- census:lanes -->
| lane | M-PX3 | M-PX4 | M-PX5 | net | total |

1. **process and memory** — the ELF loader for a static executable,
   the initial stack and auxiliary vector (below), `execve`,
   `exit_group`, `arch_prctl(ARCH_SET_FS)`, `mprotect`, the anonymous
   `brk`/`mmap`/`munmap`, `getrandom`; `set_tid_address`,
   `set_robust_list`, `rseq`, `prlimit64` and `sched_getaffinity` may
   start as `-ENOSYS` (measured above). First: everything else waits on
   `execve`.
2. **files** — the descriptor table, an initramfs file system, the
   console as descriptors 0–2; `read`, `write`, `openat`, `close`,
   `fstat`/`statx`, `lseek`, `getdents64`, `getcwd`, `unlink`,
   `readlinkat`; and the paths M-PX3 touches: `/dev/stdin`,
   `/dev/stdout`, `/dev/stderr` (wolf opens them by name on almost every
   run, wolf-lang#405), `/dev/null`, `/dev/zero`, `/dev/full`,
   `/proc/self/exe` (every static start reads it), `/proc/self/fd`,
   `/proc/self/cgroup` (`nproc`, 54 of its 78 runs),
   `/proc/sys/kernel/arch` (`printf`, 265 of its 270 runs).
3. **time** — `clock_nanosleep` (`CLOCK_MONOTONIC` and `CLOCK_REALTIME`)
   and `clock_gettime`; the vDSO can wait (below).
   **M-PX3 is testable here.**
4. **signals** — nothing in M-PX3 installs a handler. lobo needs
   `rt_sigaction`, `rt_sigprocmask`, `rt_sigreturn`, `sigaltstack`,
   `kill`; the shells add `rt_sigsuspend`. `SIGPIPE` is the most-set
   disposition in the census: 33,764 of the 35,320 `rt_sigaction` calls
   are curl's and pacman's libcurl setting it around their transfers.
5. **sockets** — lobo's 13 for M-PX4 (`socket`, `bind`, `listen`,
   `accept4`, `connect`, `epoll_*`, `poll`, `recvfrom`, `sendto`,
   `setsockopt`, `getsockname`): `AF_UNIX` (the control socket) and TCP
   on loopback can land in P3, before P4's virtio-net. lobo 0.1.1 binds
   `127.0.0.1:0`, listens and connects to itself once per generation (a
   TCP loopback pair), so loopback TCP is needed even for a lobo that
   serves nobody. The network floor adds `socketpair`,
   `sendmsg`/`recvmsg`, `getpeername`, `ppoll`, `pselect6` and
   `AF_NETLINK` (route and interface queries from glibc and curl).

M-PX4 and M-PX5 then reopen lanes 1 and 2 rather than adding new
subsystems: threads and `futex`, `clone`/`clone3`/`vfork`/`wait4`, the
identity calls (`getuid` … `setresuid`, `setgroups`), file-backed
`mmap` for `ld.so`, `fcntl`, the tty `ioctl`s, `pipe2`, `dup2`,
`umask`, `chdir`, and the permission and ownership calls. Recommended
contracts: **px-a** process and memory (M-PX3 tier), **px-b** files
(M-PX3 tier, with the paths), **px-c** time, then M-PX3; then
**px-d** process II (threads, fork, wait, identity), **px-e** signals,
**px-f** files II, **px-g** sockets (AF_UNIX, loopback TCP, epoll) for
M-PX4.

So: **the loader reads every entry at one site** (`ld.so`'s, or
`_dl_aux_init` in a static binary): it copies the vector. What it
*needs* is three: `AT_PHDR`, `AT_PHNUM`, `AT_ENTRY` for a dynamic
program; `AT_PHNUM` alone for the static one (without it the static
binary dies of SIGSEGV). Everything else falls back: no
`AT_PAGESZ`, `AT_RANDOM`, `AT_HWCAP`, `AT_SECURE` or `AT_SYSINFO_EHDR`
changed any subject's output or status. PAX should still supply the
standard set (it is cheap and glibc's choices with them missing are not
measured here beyond "the output matched"), but the first boot can be
judged on these three.

## The vDSO

strace cannot see a call the vDSO answers. With the vDSO present and
with `AT_SYSINFO_EHDR` hidden, gdb counted the time, cpu and random
system calls each subject actually made:

<!-- census:vdso -->
| subject | system calls with the vDSO → without it | result without it |
|---|---|---|
| `bore-static-seq` | no change | same |
| `bore-static-sort` | no change | same |
| `bore-static-sleep` | no change | same |
| `bore-dyn-seq` | no change | same |
| `bore-dyn-sort` | no change | same |
| `bore-dyn-sleep` | no change | same |
| `lobo-t` | no change | same |
| `dash` | no change | same |
| `bash` | `gettimeofday` 0 → 3 | same |
| `pacman` | `clock_gettime` 0 → 2 | same |
| `make` | no change | same |
| `curl` | `clock_gettime` 0 → 155, `gettimeofday` 0 → 7, `time` 0 → 38 | same |
| `sshd-t` | `clock_gettime` 0 → 1, `time` 0 → 1, `getrandom` 4 → 12 | same |
<!-- /census:vdso -->

No boreutils utility, lobo's config test, dash or make asks the vDSO
anything; bash and pacman ask it for the time a few times; curl's one
https fetch asks it about 200 times (`clock_gettime`, `gettimeofday`,
`time`), and `sshd -t` takes 8 of its 12 `getrandom`s from the vDSO. Every subject
gave the same result without it. **The vDSO is an optimisation PAX can
defer past M-PX5**; without it these become `clock_gettime`,
`gettimeofday`, `time` and `getrandom` system calls, all already in the
union.

## What the census cannot see

- **Calls the vDSO answers** (above), and any call made only on a path
  these workloads did not take: an error path, a locale, a terminal
  that is a real tty (the pty session is the one tty here), a full
  upgrade (`-Syu` had nothing to do), IPv6 (`connect` to `AF_INET6`
  addresses answered `ENETUNREACH`: the container has no IPv6 route).
- **The environment's answers.** A rootless user namespace refuses
  some identity and socket operations (`setsockopt` `EPERM` ×24 is
  `SO_RCVBUFFORCE`/`SO_SNDBUFFORCE`), and systemd is not running
  (pacman's hook says "Current root is not booted").
- **Run-to-run noise.** The trace and the `-c` run of one workload are
  two runs; their call counts differ by timing (polls, `EAGAIN`s,
  futex waits), and a rare call can appear in one and not the other:
  the static suite made `clock_gettime(CLOCK_MONOTONIC)` twice in the
  traced run and not at all in its `-c` run.
- **Timing under ptrace.** strace slows every call; the counts of
  `EAGAIN`, `ETIMEDOUT` and `poll` are those of a traced program.

## Reproduce

On a Linux host with rootless podman (kasumi, 2026-10-04; podman's
shared store there answered EIO on every overlay mount, so the census
used a lane-private store):

```sh
export CENSUS_PODMAN_ROOT=~/lanes/px04/pod   # optional: a private store
tools/census/census image     # the container image
tools/census/census stage     # wolf, boreutils x2, lobo, the reel, by digest
tools/census/census trace     # nine workloads, -ff -o then -c
tools/census/census tally     # out/<workload>.csv, paths.csv, ops.csv
tools/census/census inject    # ENOSYS, one call at a time, static and dynamic
tools/census/census probe     # the auxv and the vDSO
python3 tools/census/report.py tools/census/out docs/CENSUS.md
```

The two set runs above are
`tools/census/census inject static set keep-mmap brk,munmap,…` and
`… set keep-brk mmap,munmap,…`, then `tools/census/census inject static summary`.
